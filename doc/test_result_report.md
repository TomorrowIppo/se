## 1. 서론

### 1.1 문서 목적 및 범위
본 문서의 목적은 한국항공대학교 소프트웨어학과 개인 프로젝트로 진행된 개인용 파일 저장 및 관리 시스템 Mini Drive에 대한 블랙박스 테스팅을 수행하고 그 결과를 기록하는 데 있다. 본 문서에서는 요구사항 분석서에 명시된 기능들이 설계 대로 정확하게 동작하는지 검증한 테스트 케이스와 최종 패스 여부를 명시한다.

### 1.2 프로젝트 개요
사용자가 파일과 폴더를 안전하게 보관하고, 업로드/다운로드/검색/공유 및 실시간 미디어 스트리밍 기능을 활용하여 데이터를 효율적으로 관리할 수 있는 계층화 구조 기반의 웹 애플리케이션 저장소 시스템을 구축한다.

### 1.3 용어 정의

| 용어 | 설명 |
|------|------|
| 서버사이드 | 응용 프로그램의 비즈니스 로직 처리, DB 및 외부 스토리지 제어를 수행하는 백엔드 계층 |
| 클라이언트 | 사용자에게 시각적으로 보여지며 RESTful API를 통해 서버와 통신하는 브라우저 기반 UI |
| 테스트 오라클 | 테스트 실행 결과가 올바른지 판단하기 위해 도입한 기준 및 정답 세트 |

### 1.4 참조 문서

2. ch14 화이트박스/블랙박스 테스트 강의 자료

## 2. 테스트 개요

### 2.1 테스트 범위
본 테스트는 내부 코드를 모른다는 가정 하에 사용자 시점에서 명세 기반으로 검증하는 블랙박스 테스트(Black-box Testing)로 이루어진다.

* Web 기반 클라이언트: UI 컴포넌트 동작 정확성 및 REST API 요청 송신 검증
* 서버사이드 애플리케이션: 비즈니스 로직(Auth, File, Share Service) 제어 정확성 확인
* 데이터베이스 및 외부 스토리지: 파일 메타데이터 정합성 및 파일 물리 저장 상태 확인

### 2.2 테스트 항목 및 통과 기준

#### 2.2.1 기능별 통과 기준
* 회원가입/로그인: 이메일 형식 준수 및 암호화된 계정 정보 정합성을 만족하는 경우만 성공 처리
* 파일 및 폴더 제어: 외부 물리 스토리지와 메타데이터 DB에 에러 없이 동시 반영 시 성공 처리
* 공유 및 재생: 유효 토큰 발행을 통한 접근 권한 식별 및 미디어 스트리밍이 정상 작동 시 성공 처리

#### 2.2.2 비기능별 통과 기준
* 보안 테스트: 세션 또는 토큰이 없는 비인가 사용자의 파일 접근을 원천 차단해야 함
* 성능 및 호환성: 주요 브라우저(Chrome, Safari) 호환 및 평균 다운로드 응답 시간 2초 이내 유지

## 6. 종합 테스트 결과 및 결론

Mini Drive 시스템의 7가지 핵심 핵심 유스케이스를 기반으로 총 20개의 테스트 케이스를 설계하여 블랙박스 테스트를 진행했다. 

테스트 결과, 회원가입 형식 제한 검증 및 컴포지트 패턴 기반의 폴더 계층 관리가 요구사항 명세서의 정의와 정확히 일치하여 정상 동작함을 확인했다. 비인가 접근 차단성 및 2GB 파일 업로드 제한 요구 제약조건 역시 트랜잭션 예외 처리를 통해 안정적으로 가동되었다. 결론적으로 본 시스템은 사용자 요구사항 분석 명세를 충족하여 성공적으로 검증 완료되었다.
